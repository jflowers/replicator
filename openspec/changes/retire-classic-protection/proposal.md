## Why

PR #205 retired classic branch protection on `main`
(`protection: null` in `.github/settings.yml`) and moved
required-check enforcement to the `safe-settings: replicator
required checks` ruleset defined in `unbound-force/.github`
(`repos/replicator.yml`, unbound-force/.github#82). The
non-strict ruleset fixes the merge friction classic
protection's `strict: true` caused for open PRs behind
deps-automerge merges.

The PR rewrote the workflowtest regression test to match the
new settings.yml, but four live spec surfaces still describe
`.github/settings.yml` as the branch-protection enforcement
source, and no change re-pointed them. Review feedback on
PR #205 (comment 4701925083) flagged the divergence: the
rewrite deleted assertions CLS-FR-006 still mandates, and
`make check` no longer detects a re-introduced classic
protection block while the spec corpus claims that coverage
exists. This change re-points the specs at the ruleset as
the enforcement source and rebuilds the local regression
assertion around what this repository still owns:
`.github/settings.yml` must not manage branch protection.

## What Changes

- Modify CLS-FR-003 (ci-learnings-skip): required checks on
  `main` stay exactly `CI OK` and `Standardized CI / Run
  linters`, but their enforcement source is the safe-settings
  ruleset; `.github/settings.yml` sets `main`'s `protection`
  to `null` instead of listing `required_status_checks`.
- Modify CLS-FR-006 (ci-learnings-skip): the workflowtest
  regression test asserts the retired state — `main`'s
  `protection` is `null` and the file declares no
  `required_status_checks` — structurally, scoped to the
  `main` branch entry, replacing the deleted contexts
  assertion.
- Modify the Branch Protection requirement (ci-checks,
  from adopt-org-infra-ci): enforcement moves from
  `.github/settings.yml` to the ruleset, and the required
  pair supersedes `Build and Test` with `CI OK`.
- Modify the Code Ownership requirement
  (ci-security-hygiene): the code-owner-approval scenario's
  GIVEN re-points from the retired settings.yml key to the
  `safe-settings: code repos` organization ruleset that now
  enforces it.
- Rewrite `TestCIGatingSettings_ClassicProtectionRetired`
  in `internal/workflowtest/ci_gating_test.go` to assert the
  modified contract with structural, main-scoped assertions.

### I. Autonomous Collaboration

**Assessment**: PASS

Enforcement ownership is documented where it lives — the
unbound-force/.github repository — so agents and humans
discover branch-protection policy from an artifact, not from
tribal knowledge. The spec deltas carry the ruleset name and
path.

**Assessment**: PASS

The repository remains standalone: no runtime dependency on
unbound-force/.github is introduced, and the local test reads
only files inside this repository. Degradation is graceful —
the spec text points at the ruleset without requiring it at
build or test time.

**Assessment**: PASS

The rewritten regression test keeps the retirement observable
in `make check`: re-adding a classic protection block or a
`required_status_checks` key fails the suite with an
explanatory message. The spec deltas state the enforced
contexts verbatim.

**Assessment**: PASS

The test verifies local file state only — no network access,
no GitHub API, no external services — satisfying Constitution
IV. Verifying the live ruleset from CI is explicitly a
non-goal (tracked as follow-up work; a live-API check would
violate the same principle).
